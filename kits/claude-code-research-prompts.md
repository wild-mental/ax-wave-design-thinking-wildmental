# 서비스 아이디어 기획을 위한 데이터 기반 디자인 씽킹 · Claude Code 리서치 지시문 킷

이 킷은 교재 [실습 안내]에 나오는 지시문의 전체 문장입니다. 교재에 나온 지시문 이름으로 찾습니다. 교재 본문의 지시문은 줄인 것이고, 이 킷은 어느 고객군에나 쓸 수 있는 기본형입니다. 〈 〉 부분을 내 내용으로 바꿔 붙여 넣습니다. 예를 들어 교재의 관통 예제 「AI 기반 온라인 비즈니스 컨설팅 솔루션」이라면 〈내 고객군〉 자리에 "처음 창업해 정부지원 사업계획서를 준비하는 예비 창업가"가 들어갑니다.

## 쓰는 법

1. Claude Code 데스크톱 앱에서 내 컴퓨터의 작업 폴더 `design-thinking-worksheet/`를 엽니다.
2. 이 킷에서 지시문을 찾아 코드 상자 안의 글을 통째로 복사하고, 〈 〉 부분을 바꿔 붙여 넣습니다.
3. 파일은 `@경로`로 가리킵니다. 예) `@research/status-report.md`
4. 결과는 지시문마다 적힌 「저장할 파일」에 저장하게 합니다. 저장한 뒤에는 「점검 포인트」로 확인하고, 핵심을 `worksheet.md`의 같은 이름 칸에 옮깁니다.
5. 한 지시에는 한 가지 목적만 담습니다. 결과가 마음에 들지 않으면 처음부터 다시 쓰지 말고 "〈어느 부분〉을 〈어떻게〉 고쳐 줘"라고 이어서 요구합니다.
6. Claude Code 대신 다른 회사의 AI 코딩 도구를 쓴다면 지시문은 그대로 쓰고, `@` 파일 지정만 그 도구의 파일 첨부 방법으로 바꿉니다.

작업 폴더

```text
design-thinking-worksheet/
├── worksheet.md                  ← 자료실의 워크시트 원본을 복사한 것
├── DESIGN.md                     ← (선택) 앞 과목에서 만든 나만의 DESIGN.md 사본 (2.4절)
├── research/
│   ├── status-report.md          ← 현황 분석 리서치
│   ├── stakeholders.md           ← 이해관계자 분석
│   ├── market-tam-sam.md         ← TAM·SAM
│   ├── causes-hypotheses.md      ← 핵심 원인과 가설
│   ├── segment-map.md            ← 세그먼트 맵
│   └── solution-som.md           ← 솔루션 정의와 SOM
├── prototype/
│   └── concept-prototype.html    ← 개념 프로토타입 (1~3화면)
└── interviews/
    ├── persona-cards.md          ← 인터뷰 대상 페르소나 카드
    ├── interview-plan.md         ← JTBD 인터뷰 계획서
    ├── pair-interview-notes.md   ← 짝 롤플레잉 기록 (지시문 없이 직접 씀)
    ├── virtual-interviews.md     ← AI 가상 인터뷰 기록
    └── interview-report.md       ← 결과 보고서 · 요약 카드 · 고용·해고 여정
```

하루를 마치기 전에 이 폴더의 파일을 GitHub 웹 화면의 Add file → Upload files로 내 비공개 저장소 `design-thinking-worksheet`에 올립니다.

## 함께 지키는 작업 규칙

1. **문제부터, 해결책은 나중에.** AI는 이미 있는 비즈니스 유형이나 온라인 자료의 겉모습에 끌려 서비스 아이디어부터 내놓기 쉽습니다. 솔루션을 정하는 2.3절 전까지는 서비스 아이디어를 받지 않습니다. 결과에 아이디어 제안이 섞여 나오면 "서비스 제안 부분은 지우고 문제의 현황만 남겨 줘"라고 요구합니다.
2. **출처 링크는 필수이고, 직접 열어 확인합니다.** 수치와 주장마다 출처 링크를 붙이게 하고, 중요한 숫자는 내가 링크를 직접 열어 같은 숫자가 있는지 봅니다. 열리지 않거나 숫자가 다른 출처는 지우거나 "확인 못 함"으로 표시합니다.
3. **수치는 출처와 계산식을 함께 씁니다.** "사람 수 × 1인당 연간 금액 = 시장 규모"처럼 계산 과정을 남기고, 내가 정한 값에는 "가정"이라고 붙입니다.
4. **다른 AI 하나로 교차 확인하는 것은 선택입니다.** 시간이 있으면 같은 질문을 다른 AI 하나에 넣어 비교합니다. 두 곳에서 함께 인용하는 출처는 중요한 자료이므로 요약에 기대지 말고 원문을 직접 읽습니다.
5. **맥락이 넘치면 새 대화에 정리본만 넘깁니다.** 대답이 같은 말을 되풀이하거나, 앞에서 정한 내용을 잊거나, 이유 없이 거절하면 그 대화는 더 쓰지 않습니다. 대화를 요약해 넘기면 수치와 핵심 메모가 사라지므로, 새 대화를 열어 아래 「새 대화 첫머리 블록」과 정리된 파일(`@research/…`)만 넘깁니다.
6. **관련 없는 예시를 맥락에 넣지 않습니다.** 교재의 관통 예제 글을 내 리서치 대화에 붙여 넣으면 결과가 그 예제 쪽으로 끌려갑니다. 형식만 필요하면 표의 머리줄만 줍니다.
7. **빠른 응답용·경량 모델로 바꾸지 않습니다.** 리서치와 계획서는 깊이 생각하는 기본 모델로 합니다.
8. **결과가 너무 어려워지면 네 가지를 묻습니다.** 이 업계에서는 이 정도가 상식인가? 작업 단계를 건너뛰어 생각의 흐름이 끊겼는가? 이 수준까지 올라가면 얻는 것이 얼마나 큰가? 이해하는 데 시간이 얼마나 드는가?
9. **실제 개인 데이터를 쓰지 않습니다.** 페르소나와 가상 인터뷰는 모두 가상입니다. AI 가상 인터뷰 기록 파일 맨 위에는 안내문을 적고, 결과 보고서로 옮긴 말 끝에는 `(AI 가상 인터뷰)`를 붙입니다(교재 부록 A-4).
10. **판단은 내가 합니다.** AI는 근거를 모으고 반대 의견을 내는 스파링 상대입니다. 고르고 정하는 것은 나입니다.

새 대화 첫머리 블록 — 새 대화를 시작할 때마다 맨 앞에 붙입니다.

```text
[작업 규칙]
- 나는 「서비스 아이디어 기획을 위한 데이터 기반 디자인 씽킹」 수업에서 〈내 고객군〉이 겪는 〈내 문제 한 줄〉을 검증하고 있어. 지금 단계는 〈교재 절 이름〉이야.
- 내가 해결책을 묻기 전에는 서비스 아이디어나 비즈니스 아이템을 제안하지 마.
- 모든 수치와 주장에 출처 링크를 붙여. 링크를 붙일 수 없는 내용은 "추측"이라고 표시해.
- 수치를 계산했으면 계산식을 함께 쓰고, 내가 정한 값에는 "가정"이라고 표시해.
- 실제 개인 정보(실명·연락처·계정 아이디)는 쓰지 마.
- 결과는 내가 말한 파일에 저장하고, 저장한 뒤 무엇을 저장했는지 세 줄로 알려 줘.
```

## 고객군 후보와 임팩트 맥락 정리 지시문

- **언제 쓰나:** Day 1 · 1.2절 (디자인씽킹 2단계 · 정의). 임팩트 비즈니스 정의 기법 1단계 「문제 인식과 임팩트 맥락 잡기」를 할 때.
- **넣을 재료 파일:** 내가 먼저 떠올린 고객군 후보 2~3개 (워크시트 「내가 풀 문제를 겪는 고객군 후보와 임팩트 맥락 메모」의 후보 표)

```text
[내 고객군 후보]
1) 〈고객군 후보 1 — 누가, 어떤 상황에서 겪는 문제인지 한 줄〉
2) 〈고객군 후보 2〉
3) 〈고객군 후보 3〉

위 후보마다 임팩트 비즈니스 정의 기법 1단계 「문제 인식과 임팩트 맥락 잡기」의 질문에 답해 줘.
- 이 문제가 이 사람들에게 어떤 손실(시간·돈·건강·기회 등)을 내고 있는가?
- 문제를 풀면 경제적 가치도 함께 생길 수 있는가? 돈을 낼 사람은 누구인가? (본인, 또는 보호자·기업·지자체 같은 다른 결제 주체)
- 이 문제를 잘못 잡았을 때의 비용은 무엇인가?
- 기존 시장이 이 고객군을 외면했거나 놓쳤을 만한 이유는 무엇인가?

[규칙]
- 서비스 아이디어나 비즈니스 아이템은 제안하지 마. 문제와 맥락만 다뤄.
- "모든 사람", "사회 전체"처럼 넓은 표현이 보이면, 같은 상황을 겪는 더 좁은 고객군으로 쪼개는 방법을 제안해 줘.
- 근거로 든 사실에는 출처 링크를 붙이고, 짐작은 "추측"이라고 표시해.

마지막에 후보별로 표 하나로 정리해 줘.
열: 후보 | 겪는 문제 | 손실 | 잘못 잡았을 때의 비용 | 돈을 낼 사람 | 출처
```

- **저장할 파일:** `worksheet.md` — 결과를 읽고 내가 고객군 하나를 고른 뒤, 「내가 풀 문제를 겪는 고객군 후보와 임팩트 맥락 메모」 칸에 직접 쓰거나 "고른 고객군 〈이름〉의 내용을 이 칸에 옮겨 줘"라고 요구합니다.
- **점검 포인트**
  - 고른 고객군이 "같은 상황을 겪는 특정 집단"으로 좁혀졌는가?
  - 결과에 서비스 아이디어가 섞였다면 지웠는가?
  - 출처 링크 가운데 하나 이상을 직접 열어 보았는가?

## 현황 분석 리서치 지시문

- **언제 쓰나:** Day 1 · 1.3절 (디자인씽킹 1단계 · 공감(간접)). 임팩트 비즈니스 정의 기법 2단계 「현황 분석」을 AI 리서치로 할 때.
- **넣을 재료 파일:** `worksheet.md` (고객군·임팩트 메모)

```text
@worksheet.md 의 「내가 풀 문제를 겪는 고객군 후보와 임팩트 맥락 메모」를 읽어 줘.
내가 고른 고객군은 〈내 고객군〉이고, 이들이 겪는 문제는 〈내 문제 한 줄〉이야.

임팩트 비즈니스 정의 기법 2단계 「현황 분석」을 해 줘.
목표는 "어디가 문제인가"의 범위와 강도를 사실과 데이터로 붙잡는 거야.

[찾을 것]
1. 규모: 이 문제를 겪는 사람이 얼마나 되는가 (통계·조사·보고서)
2. 강도: 얼마나 자주, 얼마나 심하게 겪는가 (손실 금액·시간·포기율 등)
3. 원인 단서: 왜 생기는가에 대해 자료가 말하는 것
4. 범위: 지역·기간·대상을 어디까지로 볼지 제안
5. 아직 자료로 확인되지 않은 것

[규칙]
- 정성 자료(기사·인터뷰·후기)와 정량 자료(통계·조사)를 함께 찾아 줘.
- 모든 수치와 주장 옆에 출처 링크를 붙여 줘. 링크를 댈 수 없는 내용은 쓰지 마.
- 수치를 직접 계산했다면 계산식을 함께 써 줘.
- 확인되지 않은 내용은 "추측"이라고 표시해.
```

## AI 가상 인터뷰 지시문

```text
1단계 · 스크리닝
```

```text
아래 기록을 JTBD 인터뷰 결과 보고서로 정리해 줘.
- 짝 롤플레잉 기록: @interviews/pair-interview-notes.md
- AI 가상 인터뷰 기록: @interviews/virtual-interviews.md
- 인터뷰 계획서: @interviews/interview-plan.md
- 가설 목록: @research/causes-hypotheses.md

[1. 결과 보고서]
인터뷰 한 건마다 아래 칸을 채운 표를 만들어 줘.
- 인터뷰 구분: 짝 롤플레잉 / AI 가상 인터뷰
- 대상 페르소나 · 세그먼트
- 상황 (When …): 전환을 일으킨 상황적 맥락 한 문장
- 하고 싶은 일 · Job Statement (… I want to …): 해결하려는 핵심 일 한 문장
- 원하는 결과 · Desired Outcome (… so I can …): 측정할 수 있는 표현으로
- 4 Forces: Push(현 상황의 불만), Pull(새 해결책의 매력), Habit(기존 습관의 관성), Anxiety(새것에 대한 불안) 각 1~2줄
- 현재 해결책 · 임시방편
- 전환 계기 · 장벽
- 근거: 기록에 있는 발화 1~2개를 그대로 인용
- 메모

[2. JTBD 요약 카드]
가장 근거가 많은 대상 한 명을 골라 위 칸을 한 장으로 줄이고, 아래 한 문장으로 끝내 줘.
「[상황]일 때, 나는 [하고 싶은 일]을 하고 싶다. 그래야 [원하는 결과]를 얻을 수 있다.」
문장은 사람의 속성(나이·직업)이 아니라 상황으로 시작해.

[3. 4 Forces 고용·해고 여정]
같은 대상의 여정을 아래 단계 순서로 표에 정리해 줘. 칸마다 근거 종류(짝 / 가상)를 붙여.
상황적 어려움 → 현재의 나(기존 습관) → Job 발견 → 해결책 탐색 → 제품·서비스 고용 → Job 수행 → 결과(성공: 이상적인 나 / 실패: 해고하고 다시 탐색)
이어서 4 Forces 표(힘 | 방향(미는 힘/막는 힘) | 내용 | 근거)와, 미는 힘과 막는 힘 가운데 어느 쪽이 컸는지에 대한 판단을 써 줘.

[4. 가설별로 들은 것]
가설마다 지지하는 근거, 반대하는 근거, 근거 종류(짝 / 가상)를 표로 정리해 줘.

[규칙]
- 근거는 기록에 실제로 있는 발화만 인용해. 기록에 없는 발화를 지어내지 마. 근거가 없는 칸은 "근거 없음"이라고 써.

결과는 interviews/interview-report.md 에 위 네 부분 순서대로 저장해 줘.
```
