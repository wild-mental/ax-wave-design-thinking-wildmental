# Claude Code 리서치 에이전트 사용 가이드

교재: 1.2절 임팩트 비즈니스 정의 기법으로 문제 고르기 (14쪽) · 1.3절 AI 리서치로 간접 공감하기 (15쪽) · 부록 A-2 Claude Code 리서치 에이전트 사용 규칙 (42쪽) · 쓰는 날: Day 1~2 (리서치 지시문을 보낼 때마다) · 쓰는 곳: Claude Code 데스크톱 앱의 Code 탭, 작업 폴더의 `research/`

## 이 가이드에서 볼 것

Claude Code를 리서치 에이전트로 쓸 때의 한 사이클 **지시 → 결과 → 확인 → 수정**을 화면 순서대로 따라갑니다. 단계마다 "이렇게 나오면 정상"인 모습, 결과가 다를 때 다시 지시하는 말, 파일이 망가졌을 때 되돌리는 법이 있습니다. 대화가 무거워졌을 때 새 대화로 옮기는 법도 함께 다룹니다.

- 지켜야 할 규칙은 교재 1.3절 「Claude Code로 리서치할 때 지킬 네 가지」와 부록 A-2, 지시문 킷의 「함께 지키는 작업 규칙」에 있고, 지시문 전문은 [지시문 킷](../kits/claude-code-research-prompts.md)에 있습니다. 여기서는 되풀이하지 않고 손으로 하는 순서를 적습니다.
- 앱 로그인과 작업 폴더 열기는 「[작업 폴더와 워크시트 저장소 준비 가이드](workspace-repo-setup-guide.md)」 4번을 봅니다.
- 예시는 관통 예제 밖의 고객군인 **동네 도서관 이용자**(평일 저녁에만 도서관에 갈 수 있는 직장인)로 듭니다. 순서를 보여 주는 예일 뿐 정답이 아닙니다. 여러분은 1.2절에서 고른 내 고객군으로 합니다.

## 리서치 한 번의 흐름

| 단계 | 하는 일 | 이 가이드 |
|---|---|---|
| 지시 | 새 대화에 첫머리 블록과 킷 지시문을 붙여, 저장할 파일까지 적어 보냅니다 | 1 · 2 |
| 결과 | 허락 요청을 읽고 처리한 뒤, `research/`에 파일이 생겼는지 봅니다 | 3 · 4 |
| 확인 | 출처 링크를 직접 열어 수치를 맞춰 보고, 중요한 수치는 교차 확인합니다 | 5 |
| 수정 | 어긋난 곳을 한 번에 한 가지씩 다시 지시하고, 확인한 핵심만 워크시트에 옮깁니다 | 6 · 7 |

1.3절의 「현황 분석 리서치 지시문」으로 설명합니다. 「이해관계자 분석 지시문」(1.3절)과 Day 2의 리서치 지시문도 같은 순서입니다. 1.2절 「고객군 후보와 임팩트 맥락 정리 지시문」은 결과를 `worksheet.md`에 쓰고, 결과를 읽고 고객군 하나를 고르는 일은 여러분이 합니다.

## 1. 새 대화 열고 첫머리 블록 붙이기

1. Code 탭 입력창 아래의 폴더 선택이 `design-thinking-worksheet`인지 봅니다.
2. 교재의 절이 바뀔 때(예: 1.2 → 1.3)와 대화가 무거워졌을 때(8번) 새 대화를 엽니다. 새 대화를 시작하는 버튼의 위치는 앱 버전에 따라 다를 수 있습니다. 새 대화에서도 폴더 선택이 맞는지 다시 봅니다. 같은 절의 지시문 두 개(현황 분석 → 이해관계자 분석)는 한 대화에서 이어 보내도 됩니다.
3. 킷의 「새 대화 첫머리 블록」을 복사해 입력창 맨 앞에 붙이고, 〈 〉 세 곳을 바꿉니다.
   - 〈내 고객군〉 → 예) "평일 저녁에만 도서관에 갈 수 있는 직장인 이용자"
   - 〈내 문제 한 줄〉 → 예) "운영 시간이 퇴근 시간과 맞지 않아 빌린 책을 제때 반납하지 못하고 연체가 쌓인다"
   - 〈교재 절 이름〉 → 예) "1.3 AI 리서치로 간접 공감하기"
4. 블록 아래에 한 줄을 비우고 지시문을 이어 붙입니다(2번). 블록과 지시문을 한 번에 보냅니다.

## 2. 지시: 킷 지시문 고쳐 보내기

1. 킷에서 그 절의 지시문(1.3절이면 「현황 분석 리서치 지시문」)을 찾아 코드 상자 안의 글을 통째로 복사합니다.
2. 〈 〉를 모두 내 내용으로 바꾸고 〈 〉 기호도 지웁니다. 첫머리 블록에 쓴 고객군 · 문제와 같은 말로 씁니다.
3. 파일은 `@`로 가리킵니다. 입력창에 `@`를 치면 파일 이름 후보가 뜨므로 골라서 넣으면 오타가 없습니다. `research/` 안의 파일이 후보에 보이지 않으면 `@research/status-report.md`처럼 경로를 끝까지 직접 씁니다.
4. 붙여 넣은 글의 줄 바꿈은 그대로 들어갑니다. 직접 줄을 바꿀 때는 `Shift+Enter`를 씁니다. `Enter`만 누르면 바로 보내질 수 있습니다.

보내기 전에 확인합니다.

- [ ] 새 대화의 첫 지시라면 첫머리 블록이 맨 앞에 있다
- [ ] 〈 〉가 하나도 남지 않았다
- [ ] 지시문 끝의 저장할 파일 이름이 킷의 「저장할 파일」과 같다. 내가 새로 쓰는 지시에도 "결과를 `research/…`에 저장해 줘"를 붙였다
- [ ] 교재의 관통 예제 글이나 다른 사람의 결과를 붙여 넣지 않았다

## 3. 허락 요청이 뜰 때

리서치 중에 Claude Code가 웹 검색, 웹 페이지 읽기, 파일 만들기 · 고치기를 해도 되는지 물을 수 있습니다. 묻는 창의 문구와 버튼 이름은 앱 버전과 모드 선택에 따라 다르므로, 버튼 이름보다 **무엇을 허락하는지**를 읽고 누릅니다. 볼 것은 세 가지입니다. **어느 파일(주소)인가 · 무엇을 하는가 · 내가 시킨 일인가.**

| 묻는 것 | 이렇게 합니다 |
|---|---|
| 웹 검색 · 웹 페이지 읽기 | 허락합니다. 리서치에 꼭 필요합니다. 거절하면 출처 없이 답하거나 멈춥니다 |
| 작업 폴더 안의 파일 만들기 · 고치기 | 경로가 `design-thinking-worksheet` 안이고 지시문에 적은 파일이면 허락합니다 |
| 파일 지우기 | 내가 시킨 일인지 한 번 더 봅니다. 시키지 않았으면 거절합니다 |
| 작업 폴더 밖의 파일, 프로그램 설치 | 거절하고 아래 말을 보냅니다. 이 수업의 리서치에는 설치할 것이 없습니다 |

```text
작업 폴더 밖은 고치지 말고, 프로그램도 설치하지 마. 왜 그게 필요한지 먼저 설명하고, 작업 폴더 안에서 할 수 있는 방법을 알려 줘.
```

- 웹 검색을 허락할지 묻는 창이 여러 번 뜨는 것은 정상입니다. 창에 같은 종류의 요청을 다시 묻지 않게 하는 선택이 있으면 골라도 됩니다. 파일을 지우는 요청은 그때마다 직접 봅니다.
- 묻지 않고 알아서 진행하는 모드라면 창이 뜨지 않을 수 있습니다. 그때는 끝난 뒤 4번처럼 만들어진 파일을 직접 열어 확인합니다.

## 4. 결과: 파일이 생겼는지 보기

리서치는 검색하고 읽는 데 시간이 걸립니다. 중간에 새 지시를 보내지 않고 끝날 때까지 기다립니다. 끝나면 Claude Code가 첫머리 블록대로 무엇을 저장했는지 세 줄로 알려 줍니다.

**이렇게 나오면 정상입니다.**

- 작업 폴더의 `research/` 안에 `status-report.md`가 생겼습니다.
- 파일의 제목이 킷 지시문에 적힌 순서(범위 → 규모와 강도 → 원인 단서 → 문제 영향도 요약 → 아직 모르는 것 → 출처 목록)대로 있습니다.
- 「규모와 강도」 표의 줄마다 출처 링크가 있고, 확인되지 않은 내용에는 "추측"이 붙어 있습니다.
- 서비스 아이디어나 해결책 제안이 없습니다.

파일은 Finder(Windows는 파일 탐색기)에서 오른쪽 클릭 → **다음으로 열기**(Windows는 **연결 프로그램**)로 텍스트 편집기(Windows는 메모장)를 골라 엽니다. Claude Code에 "research/status-report.md 의 「규모와 강도」 표만 보여 줘. 파일은 고치지 마."라고 물어도 됩니다.

## 5. 확인: 출처를 직접 열어 보기

교재 1.3절 네 가지 가운데 "수치는 출처를 열어 확인한다"와 "교차 확인한다"를 손으로 하는 순서입니다.

### 수치 하나를 확인하는 순서

1. `research/status-report.md`의 「규모와 강도」 표에서 내 문제를 가장 강하게 보여 주는 수치 세 개를 고릅니다.
2. 그 줄의 출처 링크를 복사해 브라우저 주소창에 붙여 넣고 엽니다.
3. 열린 페이지에서 `Cmd+F`(Windows `Ctrl+F`)로 그 숫자를 찾습니다. `1,200`과 `1200`, "12만"과 "120,000"처럼 쓰는 법이 다를 수 있으니 숫자 앞부분이나 낱말로도 찾아봅니다. PDF 보고서는 PDF 화면의 찾기를 씁니다.
4. 숫자만이 아니라 **연도 · 지역 · 대상**이 내 범위와 같은지도 봅니다. 예) 내 범위는 한 도시인데 전국 통계인지, 몇 년 전 자료인지.
5. 같은 숫자를 찾았으면 그 줄에 ○, 링크가 열리지 않거나 숫자가 없거나 다르면 "확인 못 함"이라고 적습니다. 교재의 "확인 안 됨" · "확인 필요"와 같은 뜻입니다. 직접 고쳐도 되고 Claude Code에 고치게 해도 됩니다(6번 표).

### 2차 인용 알아보기

기사나 블로그가 다른 기관의 숫자를 옮겨 쓴 것이 2차 인용입니다. 이런 줄은 처음 발표한 원 출처를 열어 봐야 확인이 끝납니다. 아래 신호가 보이면 2차 인용을 의심합니다.

- 출처가 뉴스 기사 · 블로그 · 정리 사이트이고, 본문에 "~에 따르면", "~조사 결과"가 있다
- 숫자는 있는데 조사 대상 · 시기 · 조사 방법이 적혀 있지 않다
- 같은 숫자가 여러 글에 나오는데 출처가 서로 다르거나 아예 없다

원 출처를 찾게 하는 말입니다.

```text
research/status-report.md 의 〈수치〉는 〈기사·글 이름〉이 옮긴 숫자야.
이 숫자를 처음 발표한 원 출처(기관 · 보고서 이름 · 연도 · 주소)를 찾아 그 줄에 따로 적어 줘.
찾지 못하면 그 줄에 "원 출처 확인 못 함"이라고 표시해 줘. 다른 줄은 고치지 마.
```

### 교차 확인과 여러 곳이 함께 인용하는 출처

- **중요한 수치는 출처 두 곳 이상에서 확인합니다.** "〈수치〉를 다른 출처 하나에서 더 찾아 줘. 숫자가 다르면 두 출처의 조사 대상 · 연도 · 지역 차이를 나란히 적어 줘."
- **여러 결과가 함께 인용하는 출처는 원문을 읽습니다.** 그런 보고서나 조사는 그 분야 사람들이 대부분 아는 기본 자료일 가능성이 큽니다. 요약에 기대지 말고 원문을 열어 목차와 핵심 표만이라도 직접 읽어 둡니다. 짝 피드백이나 인터뷰에서 "이 문제를 조사했다면서 이 자료를 모르나?" 하는 순간을 막아 줍니다. 찾게 하는 말: "출처 목록에서 두 번 이상 인용된 출처를 골라, 원문 주소와 함께 어느 수치에 쓰였는지 보여 줘. 파일은 고치지 마."
- 시간이 있으면 같은 질문을 다른 AI 하나에 넣어 비교해도 됩니다(선택, 킷 「함께 지키는 작업 규칙」 4번).

### 확인 결과를 적는 예 (동네 도서관 이용자)

표의 모양과 표시만 보여 주는 예입니다. 〈 〉 자리에는 실제로 열어 확인한 내용이 들어갑니다.

| 사실·수치 | 출처 (링크) | 직접 열어 확인 (○) | 무엇을 말해 주는가 |
|---|---|---|---|
| 〈도시〉 공공도서관 〈몇〉 곳 가운데 평일 〈몇〉 시 넘어 여는 곳 〈몇〉 곳 | 〈도서관 운영 현황 통계 주소〉 | ○ | 퇴근 뒤 이용할 수 있는 시간이 짧다 |
| 연체 이용자 가운데 직장인 비율 〈몇〉% | 〈기사 주소〉 → 원 출처: 〈조사 보고서 이름〉 | 확인 못 함 (기사에만 있고 원 출처를 찾지 못함) | 확인 전이라 근거로 쓰지 않음 |

## 6. 수정: 다시 지시하는 말

결과가 마음에 들지 않으면 처음부터 다시 쓰지 않고, 한 번에 한 가지를 "그 부분만" 고치게 합니다(킷 「쓰는 법」 5번). 끝에 "다른 부분은 그대로 둬"를 붙이면 멀쩡한 곳이 바뀌지 않습니다.

| 이렇게 나왔다 | 다시 지시하는 말 |
|---|---|
| 서비스 아이디어 · 해결책 제안이 섞였다 | 서비스 제안 부분은 지우고 문제의 현황만 남겨 줘. |
| 출처 링크가 없는 수치가 있다 | 출처 링크가 없는 수치를 모두 목록으로 보여 줘. 출처를 찾으면 링크를 붙이고, 못 찾으면 그 줄에 "추측"을 붙여 줘. 다른 줄은 그대로 둬. |
| 링크가 열리지 않거나 숫자가 다르다 | 〈수치〉의 출처 링크를 열어 보니 같은 숫자가 없어. 그 줄을 "확인 못 함"으로 고치고, 같은 수치를 확인할 수 있는 다른 출처를 찾아 줘. |
| 계산한 숫자에 계산식이 없다 | 〈숫자〉가 어떻게 나온 값인지 계산식을 그 줄에 함께 적어 줘. 내가 정한 값에는 "가정"을 붙여 줘. |
| 범위가 너무 넓다 (예: "전국의 모든 도서관 이용자") | 범위를 〈지역〉의 〈대상〉으로 좁혀서 「범위」를 다시 써 줘. 다른 제목 아래 내용은 그대로 둬. |
| 해외 자료만 있다 | 국내 자료를 먼저 찾아 줘. 해외 자료는 줄 끝에 "해외"라고 표시해서 남겨 둬. |
| 답이 대화에만 있고 파일이 없다 | 방금 답을 research/status-report.md 로 저장해 줘. 내용은 바꾸지 마. |
| 결과가 너무 어렵다 | 킷 「함께 지키는 작업 규칙」 8번의 네 질문을 스스로 물은 뒤, "〈어려운 부분〉을 이 업계 밖의 사람도 알 수 있게 풀어 써 줘. 수치와 출처는 그대로 둬."라고 보냅니다. |

계산식은 "사람 수 × 1인당 연간 금액 = 시장 규모"처럼 숫자가 어디서 왔는지 따라갈 수 있게 씁니다. 고쳐 달라고 해도 계속 어긋나면 "무엇을 바꿀지 목록으로 먼저 보여 주고, 내가 좋다고 하면 고쳐 줘."를 붙입니다.

## 7. 핵심만 워크시트에 옮기기

1. ○ 표시한 수치와 범위 · 원인 단서 · 아직 모르는 것의 핵심만 `worksheet.md`의 「AI 리서치로 문제의 범위와 강도를 정리한 현황 분석 노트」에 옮깁니다. 리서치 전문은 `research/status-report.md`에 그대로 둡니다.
2. 직접 써도 되고, 이렇게 맡겨도 됩니다.

```text
@research/status-report.md 에서 내가 확인한 아래 수치만 @worksheet.md 의 「AI 리서치로 문제의 범위와 강도를 정리한 현황 분석 노트」 중 「규모와 강도」 표에 옮겨 줘. 「직접 열어 확인」 칸에는 ○를 적어 줘.
〈확인한 수치 1〉 / 〈확인한 수치 2〉 / 〈확인한 수치 3〉
표 칸 안에는 | 기호와 줄 바꿈을 쓰지 마. 다른 칸과 다른 산출물은 고치지 마.
```

3. "추측"이나 "확인 못 함"이 붙은 내용은 사실처럼 옮기지 않습니다. 꼭 남기려면 「직접 열어 확인」 칸에 "확인 못 함"을 그대로 적고 근거로 쓰지 않습니다.
4. 옮긴 뒤 그 산출물 끝의 **점검 질문**에 답하고 `- [ ]`를 `- [x]`로 바꿉니다.

## 되돌리기: 큰 변경 전에 복사본 남기기

리서치를 다시 돌리거나 표를 크게 바꾸면, 앞에서 확인해 둔 ○ · "확인 못 함" 표시가 사라질 수 있습니다. 큰 변경 전에는 복사본을 남깁니다. 이름은 `<원래 파일 이름>-before-<다음 작업>` 한 가지 형식으로 씁니다. 예) `research/status-report-before-cross-check.md`

```text
research/status-report.md 를 research/status-report-before-cross-check.md 로 복사해 둬. 복사본은 고치지 마. 복사가 끝나면 교차 확인을 시작해 줘.
```

결과가 망가졌으면 이렇게 되돌립니다.

```text
research/status-report.md 를 research/status-report-before-cross-check.md 와 똑같은 내용으로 되돌려 줘. 복사본 파일은 그대로 둬.
```

- 직접 되돌릴 때는 망가진 파일을 지우고, 복사본을 한 번 더 복사해 원래 이름으로 바꿉니다. 복사는 Mac Finder에서 `Cmd+D`(복제), Windows 파일 탐색기에서 `Ctrl+C` → `Ctrl+V`입니다. 복사본 자체는 늘 남겨 둡니다.
- `worksheet.md`에 크게 옮겨 적기 전에도 같은 형식으로 복사본을 남길 수 있습니다. 예) `worksheet-before-stakeholders.md`
- 이미 저장소에 올린 파일은 저장소에서 그 파일을 열고 **History**를 누르면 올렸을 때의 내용을 볼 수 있습니다. 복사본은 하루를 마칠 때 다른 파일과 함께 올라가도 괜찮습니다.

## 8. 대화가 무거워지면 새 대화로 옮기기

아래 신호가 보이면 그 대화는 더 쓰지 않습니다. 앞 내용을 제대로 붙잡지 못하는 상태라, 그 대화에서 더 고쳐 달라고 해도 믿기 어렵습니다.

- 같은 말을 되풀이한다
- 앞에서 정한 고객군이나 범위를 잊고 다시 묻는다
- 이유 없이 작업을 거절하거나, 답이 중간에 끊긴다

1. 결과가 이미 모두 `research/` 파일에 있다면 3번으로 갑니다. 대화에서 새로 정했는데 파일에 없는 것이 있으면, 지금 대화에 먼저 이렇게 보냅니다.

```text
이 대화에서 정했지만 research/status-report.md 에 아직 없는 수치(출처 링크 포함)와 결정을, 그 파일 맨 아래 "## 이어 갈 메모"에 그대로 옮겨 적어 줘. 요약하지 말고 숫자와 문장을 그대로 옮겨. 다른 부분은 고치지 마.
```

2. 파일을 열어 그 내용이 들어갔는지 봅니다.
3. 새 대화를 열고(1번), 첫머리 블록 다음에 이렇게 시작합니다.

```text
@research/status-report.md 를 읽고, 「이어 갈 메모」까지 이해한 내용을 다섯 줄로 알려 줘. 파일은 아직 고치지 마.
```

4. 다섯 줄이 맞으면 하던 지시를 이어서 보냅니다.

대화를 요약해 새 대화에 붙이지 않습니다. 요약하면 수치와 핵심 메모가 빠집니다. 새 대화에 넘기는 것은 파일뿐입니다(교재 1.3절, 킷 「함께 지키는 작업 규칙」 5번).

## 다른 AI 코딩 도구를 쓸 때

지시문은 그대로 쓰고, `@` 파일 지정만 그 도구의 방법으로 바꿉니다. 리서치에는 웹 검색이 필요하므로, 그 도구에서 웹 검색이 되는지 먼저 확인합니다. 자세한 대응은 「[다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)](../help/other-coding-tools.md)」를 봅니다.

## 자주 하는 실수와 고친 예

- **저장할 파일을 적지 않았다** — "동네 도서관 연체 현황을 찾아 줘"만 보내 답이 대화에만 남았습니다. → 이미 받은 답은 "방금 답을 research/status-report.md 로 저장해 줘. 내용은 바꾸지 마."로 파일에 남깁니다. 다음부터는 지시 끝에 저장할 파일을 붙입니다.
- **출처 링크를 열지 않고 옮겼다** — 1인 가구 리서치에서 "혼자 사는 사람의 〈몇〉%가 …" 수치를 워크시트에 옮겼는데, 나중에 열어 보니 다른 해 · 다른 나라의 조사였습니다. → 옮기기 전에 5번 순서로 열어 연도 · 지역 · 대상을 맞춰 보고, 맞지 않으면 "확인 못 함"으로 고칩니다.
- **관통 예제 글을 내 대화에 붙였다** — 표 형식을 맞추려고 교재의 창업가 예제 표를 통째로 붙였더니, 도서관 이용자 리서치에 창업 · 컨설팅 이야기가 섞였습니다. → 새 대화에서 다시 하고, 형식이 필요하면 표의 머리줄(열 이름)만 줍니다.
- **빠른 응답용 모델로 바꿨다** — 답은 빨라졌지만 출처가 줄고 내용이 얕아졌습니다. → 입력창 아래 줄 오른쪽 끝의 모델 선택을 처음 쓰던 기본 모델로 되돌리고 다시 보냅니다.
- **대화를 요약해 새 대화로 넘겼다** — 배달앱 리서치에서 요약에 숫자가 빠져, 새 대화가 출처 없는 수치를 다시 내놓았습니다. → 8번처럼 꼭 남길 수치와 문장을 파일에 옮긴 뒤 그 파일만 `@`로 넘깁니다.

## 제대로 됐는지 확인

- [ ] 지시문으로 만든 결과가 `research/` 안에 킷의 「저장할 파일」 이름으로 있다
- [ ] 가장 중요한 수치 세 개의 출처 링크를 직접 열어, 같은 숫자와 연도 · 지역 · 대상을 확인했다
- [ ] 확인하지 못한 수치에 "확인 못 함", 출처를 붙일 수 없는 내용에 "추측"이 붙어 있다
- [ ] 계산한 숫자에 계산식이, 내가 정한 값에 "가정"이 붙어 있다
- [ ] 워크시트에는 확인한 핵심만 옮겼고, 서비스 아이디어는 남아 있지 않다

## 막혔을 때

- **답이 대화에만 있고 파일이 안 생겼습니다.** "방금 답을 research/status-report.md 로 저장해 줘. 내용은 바꾸지 마."라고 보냅니다. 파일을 만들지 묻는 창을 거절했거나 놓치지 않았는지도 봅니다.
- **`@`로 가리킨 파일을 못 찾는다고 합니다.** 다른 폴더를 열었을 가능성이 큽니다. 입력창 아래 폴더 선택이 `design-thinking-worksheet`인지 보고, "이 폴더에 무엇이 있는지 알려 줘"로 확인합니다. 후보에 뜨지 않는 파일은 `@research/status-report.md`처럼 경로를 끝까지 씁니다.
- **출처 링크가 열리지 않거나 내용이 다릅니다.** 그 줄을 "확인 못 함"으로 고치고 같은 수치를 확인할 수 있는 다른 출처를 찾게 합니다(6번 표). 끝까지 열리지 않는 링크는 그럴듯하게 지어낸 주소일 수 있으니, 그 수치는 근거로 쓰지 않습니다.
- **웹을 찾아보지 않고 출처 없이 답합니다.** "웹에서 찾아서, 수치마다 출처 링크를 붙여 줘."라고 다시 보냅니다. 웹 검색을 허락할지 묻는 창을 거절했다면, 다시 지시하고 이번에는 허락합니다.
- **같은 말을 되풀이하거나 앞에서 정한 것을 잊습니다.** 그 대화는 더 쓰지 않고 8번 순서로 새 대화로 옮깁니다.
- **작업 폴더 밖의 파일을 고치거나 무엇을 설치하겠다고 합니다.** 허락하지 않고 3번의 말을 보냅니다.
- **사용 한도에 걸렸습니다.** 만든 파일은 작업 폴더에 그대로 남습니다. 다시 쓸 수 있을 때까지 출처 확인과 워크시트 옮기기를 먼저 합니다. 기다릴 수 없으면 「[다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)](../help/other-coding-tools.md)」를 봅니다.
