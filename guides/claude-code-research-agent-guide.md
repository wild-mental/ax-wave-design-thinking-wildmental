# Claude Code 리서치 에이전트 사용 가이드

교재: 1.2절 임팩트 비즈니스 정의 기법으로 문제 고르기 (14쪽) · 1.3절 AI 리서치로 간접 공감하기 (15쪽) · 부록 A-2 Claude Code 리서치 에이전트 사용 규칙 (42쪽) · 쓰는 날: Day 1~2 (리서치 지시문을 보낼 때마다) · 쓰는 곳: Claude Code 데스크톱 앱의 Code 탭, 작업 폴더의 `research/`

> **준비 중인 가이드입니다.** 수업 전에 채워집니다. 그동안은 교재 부록 A-2와 지시문 킷의 「함께 지키는 작업 규칙」을 보세요.

## 이 가이드에서 볼 것

Claude Code를 리서치 에이전트로 쓸 때의 한 사이클(지시 → 파일로 저장 → 출처를 직접 열어 확인 → 핵심만 워크시트에 옮기기)을 실제 화면 순서로 따라갑니다. 대화가 무거워졌을 때 새 대화로 옮기는 법과, 서비스 아이디어가 섞여 나올 때 다시 지시하는 말도 함께 다룹니다.

## 리서치 한 번의 흐름

1. **작업 폴더를 열고 시작합니다.** Code 탭의 폴더 선택에서 `design-thinking-worksheet`를 고릅니다(「[작업 폴더와 워크시트 저장소 준비 가이드](workspace-repo-setup-guide.md)」 4번).
2. **지시문 끝에 저장할 파일을 적습니다.** 예) "결과를 `research/status-report.md`로 저장해 줘". 앞의 결과를 다시 쓸 때는 `@research/status-report.md`처럼 `@`와 경로로 가리킵니다.
3. **출처를 직접 엽니다.** 수치와 주장마다 붙은 링크를 열어 그 내용이 실제로 있는지 봅니다. 확인하지 못한 숫자에는 "확인 필요"라고 표시합니다.
4. **핵심만 워크시트에 옮깁니다.** 리서치 전문은 `research/` 파일에 두고, `worksheet.md`에는 확인한 핵심만 옮깁니다.

지시문의 전체 문장은 [지시문 킷](../kits/claude-code-research-prompts.md)에서 교재에 나온 이름으로 찾습니다.

## 1. 지시문 보내기와 `@` 파일 지정

> [작성 예정] 킷에서 지시문을 복사해 〈 〉를 바꾸는 요령, 입력창에서 `@`를 쳐 파일을 고르는 법, 새 대화마다 킷의 「새 대화 첫머리 블록」을 맨 앞에 붙이는 법 — 실제 화면 확인 뒤

## 2. 허락 요청이 뜰 때

> [작성 예정] 웹 검색·웹 페이지 읽기·파일 만들기를 허락해 달라는 요청을 읽는 법(어느 파일인가 · 무엇을 하는가 · 내가 시킨 일인가), 작업 폴더 밖 파일을 고치겠다고 할 때 거절하고 보낼 말 — 실제 화면과 모드 이름 확인 뒤

## 3. 출처 링크를 직접 열어 확인하기

교재 1.3절의 네 규칙 가운데 두 가지를 이렇게 지킵니다.

- **수치는 출처를 열어 확인합니다.** 링크를 열어 같은 숫자가 있는지 봅니다. 없거나 열리지 않으면 지우거나 "확인 못 함"으로 적습니다.
- **교차 확인합니다.** 중요한 수치는 출처 두 곳 이상에서 확인하고, 여러 결과가 함께 인용하는 출처는 요약에 기대지 말고 원문을 읽습니다.

> [작성 예정] 2차 인용을 알아보는 법과 원 출처를 찾게 하는 다시 지시하는 말, 워크시트 「규모와 강도」 표의 "직접 열어 확인 (○)" 칸 쓰는 예 (관통 예제 밖 예시로)

## 4. 수치에 계산식과 "가정" 붙이기

AI가 계산한 숫자는 계산식과 가정을 함께 적게 합니다. 예) "사람 수 × 1인당 연간 금액 = 시장 규모". 내가 정한 값에는 "가정"을, 출처를 붙일 수 없는 내용에는 "추측"을 붙이게 합니다.

## 5. 대화가 무거워지면 새 대화로 옮기기

답이 엉뚱해지거나, 앞에서 정한 내용을 잊거나, 이유 없이 작업을 거절하면 그 대화는 더 쓰지 않습니다.

1. 지금 대화에서 꼭 남길 수치와 핵심 문장을 파일로 정리하게 합니다. 대화를 요약해 넘기지 않습니다.
2. 새 대화를 엽니다.
3. 킷의 「새 대화 첫머리 블록」을 붙이고, 정리한 파일만 `@research/…`로 넘깁니다.

> [작성 예정] 새 대화를 여는 위치, 정리 파일을 만들게 하는 다시 지시하는 말 예

## 6. 서비스 아이디어가 섞여 나올 때

솔루션을 정하는 2.3절 전까지는 서비스 아이디어를 받지 않습니다. 결과에 아이디어 제안이 섞이면 이렇게 보냅니다: "서비스 제안 부분은 지우고 문제의 현황만 남겨 줘."

## 다른 AI 코딩 도구를 쓸 때

지시문은 그대로 쓰고, `@` 파일 지정만 그 도구의 방법으로 바꿉니다. 자세한 대응은 「[다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)](../help/other-coding-tools.md)」를 봅니다.

## 자주 하는 실수와 고친 예

> [작성 예정] 3~5개, 관통 예제 밖 예시로: 저장할 파일을 적지 않아 답이 대화에만 남음 · 출처 링크를 열지 않고 옮김 · 관통 예제 글을 내 리서치 대화에 붙여 결과가 그쪽으로 끌려감 · 빠른 응답용 모델로 바꿈 · 대화를 요약해 새 대화로 넘겨 수치가 사라짐

## 제대로 됐는지 확인

- [ ] 지시문으로 만든 결과가 `research/` 안에 지시문에 적힌 파일 이름으로 있다
- [ ] 워크시트에 옮긴 수치마다 출처 링크가 있고, 그 링크를 직접 열어 보았다
- [ ] 계산한 숫자에 계산식이, 내가 정한 값에 "가정"이 붙어 있다

## 막혔을 때

> [작성 예정] 답이 대화에만 있고 파일이 안 생겼을 때 · `@`로 가리킨 파일을 못 찾을 때(다른 폴더를 연 경우) · 출처 링크가 열리지 않거나 내용이 다를 때 · 사용 한도에 걸렸을 때 · 같은 말을 되풀이할 때
