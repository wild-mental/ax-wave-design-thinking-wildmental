# 개념 프로토타입 만들기 가이드

교재: 2.4절 개념 프로토타입 만들기 (28~31쪽) · 부록 A-3 개념 프로토타입 파일 열어 보기 (43쪽) · 쓰는 날: Day 2 오전 · 쓰는 곳: 작업 폴더의 `prototype/concept-prototype.html`, 워크시트 「인터뷰에서 보여 줄 1~3화면 개념 프로토타입」

## 이 가이드에서 볼 것

Claude Code로 인터뷰에서 보여 줄 개념 프로토타입(완성품이 아니라 서비스의 인상과 개념을 보여 주려고 만든 1~3화면)을 만들고, 브라우저로 열어 확인하고, 한 번에 한 가지씩 고치는 순서를 **지시 → 결과 → 확인 → 수정**으로 따라갑니다. 개념 프로토타입이 완성품과 무엇이 다른지와, 참고 사례 GrainBridge · 중심 예제 MakersRound의 화면은 교재 2.4절을 봅니다. 만들어지는 화면은 사람마다 다르므로, 화면 캡처 대신 "이렇게 나오면 정상"을 글로 적었습니다.

| 순서 | 하는 일 | 파일 |
|---|---|---|
| 0 | 준비물 확인, 나만의 DESIGN.md 복사 | `DESIGN.md` |
| 1 | 지시문 보내고 요약 확인 → 만들기 | `prototype/concept-prototype.html` |
| 2 | 브라우저로 열어 확인 | — |
| 3 | 한 번에 한 가지씩 고치기 (큰 변경 전에는 복사본) | `prototype/concept-prototype-before-<다음 작업>.html` |
| 4 | 짝에게 10초 보여 주기 | — |
| 마무리 | 워크시트에 적기 | `worksheet.md` |

## 교재 2.4절의 두 화면

교재 2.4절에서 본 참고 사례와 중심 예제의 화면을 직접 열어 볼 수 있습니다.

| 화면 | 주소 | 볼 것 |
|---|---|---|
| 참고 사례: 식량 불균형(GrainBridge) | https://grain-bridge.vercel.app | 첫 화면의 한 문장과 주 버튼 하나, "예시 데이터" 표시. 맨 위 「한국어 / English」로 언어를 바꿉니다 |
| 중심 예제: MakersRound | https://www.makersround.world/ | 첫 화면의 한 문장 · 두 버튼 · 세 약속이 솔루션의 핵심 기능과 어떻게 이어지는지 (중심 예제로 실습한 예이며, 정답이 아닙니다) |

두 화면 모두 요금제 · 대시보드 · 운영 원칙까지 담은 긴 페이지입니다. 여러분이 만들 것은 1~3화면이므로 구성 전체를 따라 하지 말고 아래 네 가지만 봅니다.

1. **첫 화면 3초.** 첫 화면만 3초 보고 창을 가린 뒤 "누구의 어떤 일을 돕는가"를 한 문장으로 말해 봅니다. 4번에서 짝에게 할 10초 확인을 내가 먼저 해 보는 것입니다.
2. **동작하지 않아도 되는 곳.** GrainBridge의 「기부하기」를 누르면 두 단계 창이 열리고 "후원 의향 확인"에서 끝납니다. 결제 정보나 개인정보는 받지 않는다고 적혀 있습니다. 버튼 뒤가 비어 있어도 인상은 전해집니다.
3. **예시 표시를 다는 곳.** GrainBridge의 매칭 목록에는 "예시 데이터" 표시와 "예시 운송사"라는 이름이, 임팩트 숫자에는 "(예측)"이, 대시보드 아래에는 실시간 수치가 아니라는 안내가 있습니다. MakersRound의 고객 상황별 사례에도 기대 효과라는 안내가 붙어 있습니다.
4. **보는 사람이 자기를 찾게 하는 곳.** MakersRound 아래쪽 「혹시 이런 상황이신가요?」는 가상 인물 네 명의 상황을 보여 줍니다. 내 프로토타입에서는 첫 화면의 상황 한 문장이 이 일을 합니다.

## 0. 준비물

- `research/solution-som.md` (2.3절) · `research/segment-map.md` (2.2절)
- `worksheet.md`의 「내가 풀 문제를 한 장에 고정한 문제정의서」
- 앞 과목 '웹서비스 UX/UI 기획'에서 만든 나만의 DESIGN.md. 작업 폴더 맨 위(`worksheet.md` 옆)에 **`DESIGN.md`라는 이름으로 복사**해 둡니다. 교재 2.4절 지시문과 킷 「개념 프로토타입 지시문」 모두 `@DESIGN.md`로 가리킵니다. Claude Code는 작업 폴더 안의 파일만 읽게 합니다(교재 부록 A-3).

나만의 DESIGN.md가 없다면 킷 지시문에서 "디자인 규칙: @DESIGN.md" 줄을 지우고 [디자인 규칙] 첫 줄을 "흰 바탕, 짙은 남색 글자, 강조색 하나만 쓰는 깔끔한 스타일로"로 바꿔 씁니다.

**파일 이름이 `DESIGN.md`가 아니면**(예: 앞 과목에서 `my-own-DESIGN.md`로 저장했다면) 복사한 사본의 이름만 바꿉니다. 원본은 그대로 둡니다.

| 순서 | Mac (Finder) | Windows (파일 탐색기) |
|---|---|---|
| 1. 원본 파일을 골라 복사 | `Cmd+C` | `Ctrl+C` |
| 2. `design-thinking-worksheet` 폴더 맨 위(`worksheet.md`가 보이는 곳)를 열고 붙여 넣기 | `Cmd+V` | `Ctrl+V` |
| 3. 붙여 넣은 파일의 이름을 `DESIGN.md`로 바꾸기 | 파일을 고르고 `Return` | 파일을 고르고 `F2` |

Windows에서 확장자가 보이지 않으면 파일 탐색기의 보기 → 표시 → 파일 확장명을 켜고, 이름이 `DESIGN.md.md`나 `DESIGN.md.txt`가 되지 않았는지 봅니다. Claude Code에 다른 폴더의 파일을 가져오라고 시키지 않습니다(작업 폴더 밖 파일, 교재 부록 A-2).

**확인.** Claude Code에 "작업 폴더 맨 위와 research 폴더의 파일 목록을 보여 줘. 파일은 만들거나 고치지 마."라고 묻습니다. 맨 위에 `worksheet.md`와 `DESIGN.md`가, `research/`에 `segment-map.md`와 `solution-som.md`가 보이면 정상입니다.

## 1. 지시문 보내고 요약 확인

**지시.** 킷의 「[개념 프로토타입 지시문](../kits/claude-code-research-prompts.md)」을 복사해 보냅니다. 교재 2.4절 [실습 안내]의 지시문을 늘린 것이라 만들기 전에 요약부터 받습니다. 오전 리서치를 이어 온 대화가 길면 새 대화를 열고 킷의 「새 대화 첫머리 블록」을 먼저 붙입니다.

**결과.** Claude Code가 바로 만들지 않고, 읽은 내용을 다섯 줄로 요약합니다.

**확인.** 요약을 내 파일과 대조합니다.

- [ ] 요약의 대상 세그먼트가 `research/segment-map.md`의 핵심 세그먼트와 같다
- [ ] 문제가 문제정의서의 [누가] · [어떤 상황에서] · [불편]과 같다
- [ ] 솔루션 요소가 `research/solution-som.md`의 가설과 솔루션 요소 표에 있는 것뿐이다
- [ ] 디자인 규칙을 `DESIGN.md`에서 읽었다(색이나 글꼴 이야기가 나온다)
- [ ] 만들 파일이 `prototype/concept-prototype.html` 하나다

**수정.** 틀린 곳만 짚어 요약을 다시 받습니다. 아직 만들게 하지 않습니다.

| 이렇게 나왔다 | 다시 지시하는 말 |
|---|---|
| 대상 세그먼트가 핵심 세그먼트와 다르거나 너무 많다 | 대상은 핵심 세그먼트 〈핵심 세그먼트 이름〉이야. @research/segment-map.md 의 「핵심 세그먼트 분석」을 다시 읽고 요약을 고쳐 줘. 아직 만들지 마. |
| 내 파일에 없는 기능이 들어 있다 | 요약의 〈기능〉은 solution-som.md 에 없어. 빼고, 가설과 이어진 요소만으로 다시 요약해 줘. |
| DESIGN.md 이야기가 없다 | @DESIGN.md 를 읽었는지 알려 주고, 색 · 글꼴 · 간격 규칙을 세 줄로 요약해 줘. |

요약이 맞으면 "좋아. 이대로 만들어 줘."라고 보냅니다. 파일을 만들어도 되는지 묻는 허락 요청이 뜨면, 만들 파일이 작업 폴더 안의 `prototype/concept-prototype.html`인지 보고 허락합니다(허락 요청 읽는 법: 「[Claude Code 리서치 에이전트 사용 가이드](claude-code-research-agent-guide.md)」의 「허락 요청이 뜰 때」).

**이렇게 나오면 정상입니다.** `prototype/` 안에 `concept-prototype.html`이 생기고, Claude Code가 화면마다 "보여 줄 핵심 인상 한 줄"과 "이어지는 가설"을 표로 정리해 줍니다. 이 표는 워크시트에 옮길 재료입니다.

## 2. 브라우저로 열어 보기

1. Finder(Windows는 파일 탐색기)에서 `prototype/concept-prototype.html`을 더블클릭해 브라우저로 엽니다. 다른 앱이 열리면 맨 아래 「막혔을 때」 첫 항목을 봅니다.
2. 직접 눌러 보며 인터뷰에서 보여 줄 인상이 드러나는지 봅니다.
3. 고친 내용이 보이지 않으면 강력 새로 고침(Mac `Cmd+Shift+R`, Windows `Ctrl+Shift+R`)을 합니다. 그래도 그대로면 파일 이름과 위치를 확인합니다.

**확인.** 아래를 보고, 걸리는 것은 고치기 전에 번호를 붙여 메모해 둡니다.

- [ ] 화면이 1~3개이고, 첫 화면에 핵심 세그먼트의 상황 한 문장과 주 버튼 하나가 있다
- [ ] 버튼으로 화면 사이를 오가고 첫 화면으로 돌아올 수 있다
- [ ] 화면의 문장과 기능이 문제정의서와 `solution-som.md`에 있는 것이다
- [ ] 숫자 · 사람 이름 · 사례 옆에 "예시"가 있고, 실제 개인 정보가 없다
- [ ] 외부 글꼴 · 이미지 없이 이 파일 하나로 열린다

## 3. 한 번에 한 가지씩 고치기

한 지시에는 한 가지 목적만 담습니다. 킷의 「이어서 줄 수 있는 지시 예」를 내 내용으로 바꿔 쓰거나, 아래 틀에 맞춰 씁니다.

```text
〈화면 이름〉의 〈영역〉이 지금 〈현재 모습〉이야.
〈바뀌어야 할 모습〉으로 바꿔 줘. 〈바꾸지 말 것〉은 그대로 둬.
```

**결과 → 확인.** Claude Code가 고친 곳을 알려 주면 브라우저에서 강력 새로 고침을 하고, 지시한 곳만 바뀌었는지 봅니다.

| 이렇게 나왔다 | 다시 지시하는 말 |
|---|---|
| 첫 화면에 기능이 너무 많다 | 첫 화면에는 〈핵심 세그먼트〉의 상황 한 문장과 주 버튼 「〈버튼 이름〉」 하나만 남겨 줘. 나머지 기능 소개는 화면 2로 옮기거나 빼고, 뺀 것은 목록으로 알려 줘. |
| 지어낸 기능이나 숫자가 들어갔다 | 〈화면 이름〉의 〈기능이나 숫자〉는 solution-som.md 와 문제정의서에 없어. 빼 줘. 다른 곳은 바꾸지 마. |
| 예시 데이터에 "예시" 표시가 빠졌다 | 화면의 숫자 · 사람 이름 · 사례마다 "예시"를 붙여 줘. 사람 이름은 누가 봐도 가상인 이름으로 바꿔 줘. |
| 고쳤더니 다른 곳도 바뀌었다 | 방금 수정에서 〈바뀐 곳〉도 바뀌었어. 그 부분만 수정 전으로 되돌려 줘. |

수정은 두세 번이면 충분합니다. 인상이 전해지면 다듬기를 멈추고 4번으로 넘어갑니다. 결과가 계속 어긋나면 지시 끝에 "무엇을 바꿀지 목록으로 먼저 보여 주고, 내가 좋다고 하면 고쳐 줘."를 붙입니다.

## 큰 변경 전에 복사본 만들기

큰 변경 전에는 Claude Code에 "지금 파일의 복사본을 만들어 두고 고쳐 줘"라고 합니다(교재 부록 A-3). 복사본 이름은 `<원래 파일 이름>-before-<다음 작업>` 한 가지로 씁니다. 예) `prototype/concept-prototype-before-second-screen.html`

화면을 하나 더하기, 첫 화면 배치를 통째로 바꾸기, 디자인 규칙 바꾸기가 큰 변경입니다. `<다음 작업>`은 영문 소문자와 하이픈으로 짧게 씁니다(예: 화면 2를 더하기 전 `second-screen`, 첫 화면 배치를 바꾸기 전 `new-layout`).

```text
지금 prototype/concept-prototype.html 을 prototype/concept-prototype-before-second-screen.html 로 복사해 두고, 그다음에 〈할 일〉을 해 줘. 복사본은 고치지 마.
```

직접 복사해도 됩니다. Mac은 Finder에서 파일을 고르고 `Cmd+D`(복제)를 누른 뒤 이름을 고치고, Windows는 파일 탐색기에서 `Ctrl+C` · `Ctrl+V`를 누른 뒤 `F2`로 이름을 고칩니다.

**되돌리기.** 고친 파일이 망가졌으면 이렇게 지시하고 강력 새로 고침을 합니다.

```text
prototype/concept-prototype.html 을 prototype/concept-prototype-before-second-screen.html 과 똑같은 내용으로 되돌려 줘. 복사본 파일은 그대로 둬.
```

직접 되돌릴 때는 망가진 파일을 지우고, 복사본을 한 번 더 복제해 이름을 `concept-prototype.html`로 바꿉니다. 복사본은 늘 남겨 둡니다.

## 4. 짝에게 10초 보여 주기

첫 화면을 짝에게 10초 보여 주고 "무슨 서비스 같아?"라고 묻습니다. 내가 의도한 인상과 비슷한 답이 나오는지 봅니다(킷 「개념 프로토타입 지시문」의 점검 포인트).

1. 첫 화면을 띄운 노트북을 짝 쪽으로 돌려 10초만 보여 주고 화면을 닫습니다. 그동안 설명하지 않습니다.
2. "무슨 서비스 같아?"라고 묻고 짝의 답을 그대로 메모합니다.
3. 의도한 인상(누구의 어떤 불편을 어떻게 덜어 주는가)과 견줍니다. 다르면 짝이 무엇을 보고 그렇게 생각했는지 한 번 묻고, 첫 화면 문장만 고친 뒤 다시 10초 보여 줍니다.

## 워크시트에 적기

「인터뷰에서 보여 줄 1~3화면 개념 프로토타입」 표에 화면마다 화면 이름, 보여 줄 핵심 인상 한 줄, 이어지는 가설을 적습니다. 파일 경로는 `prototype/concept-prototype.html`입니다. 1번에서 Claude Code가 준 표를 재료로 쓰되, 내가 브라우저로 본 대로 고쳐 씁니다.

| 칸 | 쓰는 것 |
|---|---|
| 화면 이름 | 파일 안의 화면 제목과 같은 이름 |
| 보여 줄 핵심 인상 (한 줄) | 짝이 10초 뒤 말해 주기를 바라는 문장 |
| 이어지는 가설 | 가설 번호와 짧은 이름 (`research/solution-som.md`와 같게) |
| 쓴 디자인 규칙 | 둘 가운데 해당하지 않는 쪽을 지웁니다. "그 밖"이면 킷에서 바꿔 쓴 첫 줄을 적습니다 |
| 인터뷰에서 보여 주는 순서와 한 줄 설명 | 화면 1 → 2 → 3 순서와, 열면서 할 말 한 줄 (예: "아직 없는 서비스의 인상을 보여 주는 화면입니다. 보이는 대로 말씀해 주세요.") |
| 일부러 만들지 않은 것 | 로그인 · 결제 · 실제 계산처럼 인상과 관계없어 뺀 것 |

완료 기준 체크리스트는 이렇게 확인합니다.

| 완료 기준 | 이렇게 확인합니다 |
|---|---|
| 인터뷰에서 보여 줄 핵심 인상이 1~3화면 안에 드러나는가? | 4번에서 짝의 답이 「보여 줄 핵심 인상」과 비슷했는지 봅니다 |
| 화면마다 이어지는 가설이 있는가? | 「이어지는 가설」 칸에 빈칸이 없고, 그 가설이 `solution-som.md`에 있는지 봅니다 |
| 내 노트북에서 파일을 더블클릭해 바로 열 수 있는가? | 브라우저를 모두 닫고 Finder(Windows는 파일 탐색기)에서 더블클릭해 봅니다 |
| 화면에 실제 개인 정보가 없고, 예시 데이터에는 "예시"라고 표시했는가? | 화면의 숫자 · 이름 · 사례를 하나씩 보며 "예시"가 붙었는지, 실제로 아는 사람의 이름이나 연락처가 없는지 봅니다 |

## 인터뷰 때 보여 주기

프로토타입은 배포하지 않습니다. 짝 롤플레잉(2.6절)에서 질문이 끝난 뒤 내 노트북에서 열어 보여 주고, 묻지 않고 지켜보며 짝이 처음 멈춘 곳과 되묻는 말을 적습니다.

## 자주 하는 실수와 고친 예

- **화면이 3개를 넘었다** (동네 도서관 좌석 예약 예: 로그인 · 회원가입 · 좌석 지도 · 예약 내역 · 설정까지 다섯 화면) → 첫 화면과 좌석 현황 화면 둘만 남깁니다. "화면을 첫 화면과 〈핵심 기능〉 화면 둘로 줄여 줘. 뺀 화면은 목록으로 알려 줘." 뺀 것은 「일부러 만들지 않은 것」에 적습니다.
- **가설과 이어지지 않는 기능이 들어갔다** (배달앱 예: 동네 가게의 수수료 부담이 문제인데 "맛집 랭킹"과 "쿠폰함"이 생겼다) → "〈기능〉은 어느 가설과 이어지는지 말해 줘. 이어지는 가설이 없으면 빼 줘."
- **실제로 동작하게 만들려다 시간을 다 썼다** (1인 가구 장보기 예: 장바구니 금액이 진짜로 계산되게 고치느라 30분) → 버튼을 누르면 "이런 결과가 나옵니다" 같은 예시 화면으로 넘어가면 충분합니다. GrainBridge의 후원 창도 "후원 의향 확인"에서 끝납니다.
- **다른 폴더의 DESIGN.md를 가리켰다** (`@../my-own-DESIGN.md`처럼 작업 폴더 밖 경로) → Claude Code가 읽지 못하거나 폴더 밖을 뒤지게 됩니다. 0번(준비물)대로 작업 폴더 맨 위에 `DESIGN.md`로 복사하고 `@DESIGN.md`로 가리킵니다.
- **외부 글꼴 · 이미지를 불러와 인터뷰 장소에서 깨졌다** (동네 헬스장 예: 인터넷에 있는 운동 사진 주소를 넣음) → "외부 글꼴 · 이미지 · 라이브러리를 모두 빼고, 사진 자리는 글자나 단순한 도형 상자로 바꿔 줘." 나만의 DESIGN.md가 외부 글꼴을 쓰고 있어도 같은 말로 기본 글꼴로 바꾸게 합니다. 와이파이를 잠시 끄고 강력 새로 고침해 확인합니다.

## 막혔을 때

- **더블클릭하면 브라우저가 아니라 다른 앱이 열립니다.** Mac은 파일을 오른쪽 클릭 → 다음으로 열기에서 Chrome이나 Safari를, Windows는 오른쪽 클릭 → 연결 프로그램에서 Chrome이나 Edge를 고릅니다. 늘 브라우저로 열리게 하려면 Mac은 `Cmd+I`(정보 가져오기)의 다음으로 열기에서 브라우저를 고르고 「모두 변경」을, Windows는 연결 프로그램 → 다른 앱 선택에서 브라우저를 고르고 「항상」을 누릅니다.
- **화면이 하얗게 나옵니다.** "브라우저로 열면 화면이 비어 있어. 원인을 찾아 쉬운 말로 설명하고, 그 부분만 고쳐 줘."라고 보냅니다. 두 번 해도 안 되면 복사본으로 되돌립니다(「큰 변경 전에 복사본 만들기」).
- **버튼을 눌러도 다음 화면으로 가지 않습니다.** "〈화면 이름〉의 「〈버튼 이름〉」을 누르면 〈다음 화면〉으로 가야 하는데 아무 일도 없어. 이 버튼만 이어 주고, 다른 곳은 바꾸지 마."라고 보냅니다.
- **DESIGN.md를 찾지 못한다고 합니다.** 0번(준비물)의 확인 질문으로 작업 폴더 맨 위의 파일 목록을 봅니다. `DESIGN.md`가 없으면 0번대로 복사하고, 이름이 `DESIGN.md.txt`나 `DESIGN (1).md`처럼 다르면 `DESIGN.md`로 고칩니다.
- **고쳤다는데 화면이 그대로입니다.** 강력 새로 고침(Mac `Cmd+Shift+R`, Windows `Ctrl+Shift+R`)을 합니다. 그래도 같으면 브라우저 주소창 끝이 `-before-`가 붙은 복사본이 아니라 `prototype/concept-prototype.html`인지 봅니다. Safari에서 글자만 남은 읽기 화면으로 바뀌면 같은 키를 한 번 더 눌러 돌아온 뒤, 탭을 닫고 파일을 다시 더블클릭합니다.
- **작업 폴더 밖 파일을 고치거나, 무엇을 설치하거나, 배포하겠다고 합니다.** 허락하지 않고 "작업 폴더 안에서, 외부 라이브러리 없이 HTML과 CSS로만 해 줘. 배포는 하지 않아."라고 보냅니다.
- **대화가 길어져 앞에서 정한 것을 잊습니다.** 새 대화를 열고 킷의 「새 대화 첫머리 블록」을 붙인 뒤 "@prototype/concept-prototype.html 과 @research/solution-som.md 를 읽고, 지금 화면 목록과 화면마다 이어지는 가설을 알려 줘. 파일은 고치지 마."로 시작합니다. 만든 것은 파일에 남아 있으므로 이어서 할 수 있습니다.
