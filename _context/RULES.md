# 온라인 자료 작성 규칙

인쇄본 교재(2026-11-20 조판본, 컬러판 · 흑백판 47쪽, 두 판의 쪽 번호 같음)와 같은 규칙입니다. 상위 프로젝트 `docs/4-2/TEXTBOOK_SPEC.md`(§1-4-7 · §1-4-10 · §1-4-12 · §1-4-14)와 `docs/4-2/PRODUCTION_LOG.md` 「구성 기준」에서 온라인 자료에 해당하는 것만 옮기고, 4-1 자료실(`wild-mental/ax-wave-uxui-wildmental`)의 `_context/RULES.md`에서 같은 방식을 이어받았습니다.

> 이 저장소는 GitHub Pages로 **공개**됩니다. `_context/`는 사이트에는 안 보이지만 저장소에서는 누구나 볼 수 있습니다. 강사용 내용(피드백 운영, 차시 운영 시간, 설계 의도, 원자료와 그 정정 메모)은 여기에도 넣지 않습니다. 그런 내용은 상위 프로젝트의 강사용 문서 `docs/4-2/instructor-guide.md`(비공개)에만 둡니다. 원자료(강사의 노션 자료)는 상위 프로젝트 `docs/4-2/sources/`에 있으며, 어떤 원자료를 어느 페이지에 싣는지는 비공개 작업 계획 `docs/4-2/ONLINE_MATERIALS_PLAN.md`에만 적습니다.

## 1. 쓰는 말

1. 학생에게 하는 말만 씁니다. 독자는 "여러분", 문체는 합니다체. 안내형("~합니다", "~하세요"). 학생을 부르는 다른 말(§8 점검 명령에 걸리는 말)은 쓰지 않습니다.
2. 설계 의도("이 수업은 ~하려고"), 피드백 기준과 운영, 차시별 운영 시간, 강사에게 하는 말은 쓰지 않습니다.
3. 전문용어는 처음 나올 때 `원어(우리말: 한 줄 풀이)`. 교재 부록 B 「용어 풀이」와 같은 풀이를 씁니다.
4. 예제를 인용할 때는 "관통 예제로 실습한 예"라고 씁니다. 짝 인터뷰 역할은 교재 그대로 "묻는 나 / 답하는 짝".

## 2. 정답처럼 보이는 것을 싣지 않기

- 학생은 각자 고른 고객군의 문제로 실습합니다. 특정 고객군의 "모범 답"이나 완성 산출물을 정답처럼 싣지 않습니다.
- 관통 예제는 교재가 이미 보여 준 것과 「관통 예제 리서치 보고서 전문」에 싣기로 한 것만 씁니다. 관통 예제는 본보기이지 정답이 아니라고 함께 적습니다.
- "실수 → 고친 예"는 관통 예제 밖(동네 도서관, 배달앱, 1인 가구 등 일반 사례)에서 가져옵니다.
- 피드백은 워크시트 칸 끝의 **점검 질문**까지만 싣습니다. 그 밖의 피드백 기준과 주는 법은 싣지 않습니다.

## 3. 개인정보와 가상 표시

- 실제 사람의 이름 · 연락처 · 계정 아이디를 쓰지 않습니다. 관통 예제 인물(김예비 · 박사장 · 최민혁 · 한서윤 · 정팀장 · 마이클 · 박은숙 · 오다빈 · 윤박사 · 이대표)은 모두 가상 인물이라고 밝힙니다.
- 인터뷰에서 옮긴 말에는 끝에 `(짝 롤플레잉)` · `(AI 가상 인터뷰)` · `(실제 인터뷰)` 가운데 하나를 붙입니다(교재 부록 A-4).
- 캡처에 개인 계정 이메일 · 실명 · 알림이 보이면 가리고 올립니다. 수업 참여자끼리 주고받는 이메일은 가릴 필요가 없지만, 이 저장소는 인터넷에 공개되므로 캡처에서는 가립니다.

버전 기호(영문 V와 숫자), 차시 기호(숫자와 H), 결정 번호(T와 숫자), 수업에서 다루지 않는 기법의 약어를 쓰지 않습니다. 풀네임과 지시문 이름만 씁니다. 사분면 이름 Q1~Q4는 교재와 워크시트에 있으므로 씁니다.

## 6. 한 곳 원칙

교재에 있는 칸 설명 · 예제 · 지시문 전문은 가이드에서 되풀이하지 않고 "교재 1.4절의 [실습 안내]"처럼 가리킵니다. 지시문 전문은 지시문 킷 한 곳에만 둡니다. 가이드는 교재에 없는 것(화면 위치, 실수와 고친 예, 점검 질문 확인 방법, 다시 지시하는 말, 막혔을 때)을 채웁니다. 교재가 그대로 인쇄한 짧은 규칙(예: 가상 인터뷰의 세 규칙, 20분 질문 세트)은 가이드에서 바로 쓸 수 있게 옮겨도 됩니다.

## 7. 형식

- 표준 마크다운(GitHub 표 · 체크리스트 포함). HTML은 쓰지 않습니다(자리표시의 작성자용 주석 한 줄만 예외, 본문을 쓰면 지움).
- 자리표시: 맨 위 `> **준비 중인 가이드입니다.** …`, 아직 쓰지 않은 칸은 `> [작성 예정] 무엇을 쓸지`, 맨 아래 `<!-- 작성자용 … -->` 다음에 「작성 계획」. 다 쓰면 셋 모두 지웁니다.
- 이미지는 `guides/images/<가이드 파일 이름>-<번호>.png`에 두고 `![설명](images/…)`로 연결합니다. 자리는 `> [캡처 예정] 공통: 무엇`으로 표시합니다.
- 화면 녹화(동영상 · GIF)는 만들지 않습니다.
- 캡처는 꼭 필요한 곳에만 둡니다: 아이콘만 있거나 메뉴 속에 숨어 글로 찾기 어려운 버튼 · 선택. AI가 만든 결과 화면, 폴더 창, 답변 화면, 글자로 이름이 적힌 버튼은 찍지 않고 글로 씁니다. 지금 캡처 자리는 2곳(「작업 폴더와 워크시트 저장소 준비 가이드」)입니다.
- 도구 조작 가이드(「작업 폴더와 워크시트 저장소 준비 가이드」 · 「Claude Code 리서치 에이전트 사용 가이드」)는 맨 아래에 "화면 확인 날짜: YYYY-MM-DD"를 적습니다.

## 8. 점검 명령

가이드를 고친 뒤 저장소 맨 위에서 실행합니다. 걸린 줄은 모두 이유가 있어야 합니다.

```
python3 -I _context/check-hub.py
grep -rnE '학[습]자|강사[ ]가이드|SaaS[형]|\b[vV][0-9]\b|\b[1-8]H\b|\bT[0-9]+\b|AOS|DOS|용어집|<[a-z]' README.md pre-course-notice.md guides help worksheet-template/README.md
```

`check-hub.py`는 ① 인쇄본의 가이드 이름마다 제목(`#` 줄)이 같은 가이드 파일이 정확히 하나인지, ② README · 가이드 · 도움말의 상대 링크가 모두 있는 파일을 가리키는지, ③ 금지어가 저장소 어디에도 없는지, ④ 워크시트 원본과 지시문 킷이 상위 프로젝트 원본과 같은지 확인합니다(①④는 상위 프로젝트가 옆에 있을 때 원고와 대조).
