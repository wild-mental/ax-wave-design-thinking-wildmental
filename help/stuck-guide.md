# 막혔을 때 모음

수업 중에 막혔을 때 도구별로 빨리 찾아보는 페이지입니다. 단계별 방법은 항목 끝의 가이드에 다 있습니다.

## 먼저 해 볼 것

1. **같은 폴더를 열었는지 봅니다.** Claude Code의 폴더 선택에서 하위 폴더가 아니라 `design-thinking-worksheet` 맨 위 폴더를 엽니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
2. **답이 엉뚱해지면 새 대화로 옮깁니다.** 남길 수치와 핵심 문장을 파일로 정리하게 한 뒤, 새 대화에 그 파일만 `@`로 넘깁니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」
3. **고쳤는데 화면이 그대로면 강력 새로 고침을 합니다.** Mac `Cmd+Shift+R`, Windows `Ctrl+Shift+R`. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」
4. **Claude Code를 쓸 수 없으면 다른 도구로 이어 갑니다.** 지시문은 그대로 쓰고 `@` 파일 지정만 바꿉니다. 자세히: 「[다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)](other-coding-tools.md)」

그래도 안 되면 손을 들어 현장에서 도움을 받습니다.

## Claude Code (작업 폴더 · 리서치)

### 작업 폴더

- **`worksheet.md`를 찾을 수 없다고 한다** → 폴더 선택에서 다운로드 폴더나 하위 폴더를 열었거나, 파일 이름이 `worksheet.md`가 아닙니다. `design-thinking-worksheet` 맨 위 폴더를 다시 고르고 파일 이름을 확인합니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
- **세 폴더가 엉뚱한 곳에 생겼다** → "방금 만든 세 폴더가 어디에 있는지 전체 경로로 알려 줘."라고 묻고, `design-thinking-worksheet` 바로 아래가 아니면 폴더 선택을 다시 한 뒤 지시문을 다시 보냅니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
- **작업 폴더를 준비하다 `worksheet.md`를 고치겠다고 한다** → 허락하지 않고 "worksheet.md는 고치지 마. 세 폴더만 만들어 줘."라고 보냅니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」

### 리서치

- **답이 대화에만 있고 파일이 안 생겼다** → "방금 답을 research/status-report.md 로 저장해 줘. 내용은 바꾸지 마."라고 보냅니다. 파일을 만들지 묻는 창을 거절했거나 놓치지 않았는지도 봅니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」
- **`@`로 가리킨 파일을 못 찾는다고 한다** → 입력창 아래 폴더 선택이 `design-thinking-worksheet`인지 보고 "이 폴더에 무엇이 있는지 알려 줘"로 확인합니다. 후보에 뜨지 않는 파일은 `@research/status-report.md`처럼 경로를 끝까지 씁니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」
- **출처 링크가 열리지 않거나 내용이 다르다** → 그 줄을 "확인 필요"로 고치고 같은 수치를 확인할 수 있는 다른 출처를 찾게 합니다. 끝까지 열리지 않는 링크의 수치는 근거로 쓰지 않습니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」
- **웹을 찾아보지 않고 출처 없이 답한다** → "웹에서 찾아서, 수치마다 출처 링크를 붙여 줘."라고 다시 보냅니다. 웹 검색을 허락할지 묻는 창을 거절했다면 이번에는 허락합니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」
- **같은 말을 되풀이하거나 앞에서 정한 것을 잊는다** → 그 대화는 더 쓰지 않습니다. 남길 수치와 결정을 파일에 옮기게 한 뒤, 새 대화에 그 파일만 `@`로 넘깁니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」
- **작업 폴더 밖의 파일을 고치거나 무엇을 설치하겠다고 한다** → 허락하지 않고 "작업 폴더 밖은 고치지 말고, 프로그램도 설치하지 마. 왜 그게 필요한지 먼저 설명하고, 작업 폴더 안에서 할 수 있는 방법을 알려 줘."라고 보냅니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」
- **사용 한도에 걸렸다** → 만든 파일은 작업 폴더에 그대로 남습니다. 다시 쓸 수 있을 때까지 출처 확인과 워크시트 옮기기를 먼저 하고, 기다릴 수 없으면 「[다른 AI 코딩 도구로 할 때 (OpenAI Codex · Cursor)](other-coding-tools.md)」를 봅니다. 자세히: 「[Claude Code 리서치 에이전트 사용 가이드](../guides/claude-code-research-agent-guide.md)」

## 문제나무 · 시장 분석

### 문제나무와 5 Whys

- **핵심 문제 후보가 모두 마음에 들지 않는다** → 가장 가까운 후보를 골라 "이 후보를 내 고객군 〈누구〉의 〈어떤 상황〉으로 좁혀 다시 세 개 제안해 줘."라고 보냅니다. 그래도 멀면 한 문장을 직접 쓰고, 너무 크거나 작은지만 물어봅니다. 자세히: 「[문제나무와 5 Whys 작성 가이드](../guides/problem-tree-5-whys-guide.md)」
- **뿌리가 끝없이 늘어난다** → "근거 파일이 있는 뿌리만 남기고 두세 묶음으로 나눠 줘. 묶음마다 이름을 붙여 줘."라고 보내고, 묶은 결과를 「원인 묶음과 핵심 원인」 표에 옮깁니다. 자세히: 「[문제나무와 5 Whys 작성 가이드](../guides/problem-tree-5-whys-guide.md)」
- **근거 파일에 없는 원인을 덧붙인다** → "방금 목록의 항목마다 근거 파일과 그 파일의 문장을 그대로 옮겨 보여 줘. 찾지 못한 항목은 지우지 말고 '추측'으로 표시해 줘."라고 보냅니다. "추측"이 붙은 항목은 내가 지우거나 인터뷰에서 확인할 것으로 남깁니다. 자세히: 「[문제나무와 5 Whys 작성 가이드](../guides/problem-tree-5-whys-guide.md)」
- **Claude Code가 "왜?"의 답까지 써 버린다** → "답은 내가 쓸게. 다음 '왜?' 하나만 물어 줘."라고 보냅니다. 자세히: 「[문제나무와 5 Whys 작성 가이드](../guides/problem-tree-5-whys-guide.md)」
- **증상인지 원인인지 판단이 서지 않는다** → 「증상과 원인 가르기」의 두 질문을 그 항목 하나에만 해 봅니다. 그래도 모르겠으면 가지에 두고, "왜?"를 한 번 물어 나온 답을 뿌리에 적습니다. 자세히: 「[문제나무와 5 Whys 작성 가이드](../guides/problem-tree-5-whys-guide.md)」

### TAM·SAM·SOM과 세그먼트 맵

- **내 고객군을 직접 센 통계가 없다** → 내 고객군을 포함하는 더 큰 통계 두세 개와 거기서 비율을 추정할 근거를 찾아 계산식으로 보여 달라고 하고, 출처 없는 비율은 "추측"으로 받은 뒤 내가 검토해 받아들인 것만 "가정"으로 바꿉니다. 자세히: 「[TAM·SAM·SOM과 세그먼트 맵 가이드](../guides/tam-sam-som-segment-map-guide.md)」
- **글로벌 시장 숫자만 가져온다** → "글로벌 숫자는 참고로 한 줄만 남기고, 〈국내〉 기준 숫자를 정부 통계나 공공 기관 · 협회 자료에서 다시 찾아 줘. 없으면 없다고 써 줘."라고 보냅니다. 자세히: 「[TAM·SAM·SOM과 세그먼트 맵 가이드](../guides/tam-sam-som-segment-map-guide.md)」
- **계산식이 이해되지 않는다** → 계산식을 한 단계씩 풀고, 숫자마다 출처에서 온 것인지 · 가정인지 · 앞 계산에서 나온 것인지 표로 보여 달라고 합니다(숫자는 바꾸지 않게). 그래도 모르겠는 숫자에는 "확인 필요"를 붙여 둡니다. 자세히: 「[TAM·SAM·SOM과 세그먼트 맵 가이드](../guides/tam-sam-som-segment-map-guide.md)」
- **TAM과 SAM이 거의 같거나 SAM이 더 크다** → 두 숫자의 단위나 기준 연도가 다를 때가 많습니다. "TAM과 SAM의 단위 · 기준 연도 · 출처를 나란히 보여 주고, 같은 기준으로 맞춰 다시 계산해 줘."라고 보냅니다. 자세히: 「[TAM·SAM·SOM과 세그먼트 맵 가이드](../guides/tam-sam-som-segment-map-guide.md)」
- **세그먼트가 넷으로 나뉘지 않는다** → 두 축이 같은 것을 잴 때가 많으니 축 하나를 후보의 다른 것으로 바꿉니다. 그런 사람이 정말 없는 사분면이면 "대상 아님"과 이유를 적는 것도 결과입니다. 자세히: 「[TAM·SAM·SOM과 세그먼트 맵 가이드](../guides/tam-sam-som-segment-map-guide.md)」

## 개념 프로토타입

- **더블클릭하면 브라우저가 아니라 다른 앱이 열린다** → 파일을 오른쪽 클릭하고 Mac은 다음으로 열기, Windows는 연결 프로그램에서 브라우저를 고릅니다. 늘 브라우저로 열리게 하는 법도 가이드에 있습니다. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」
- **화면이 하얗게 나온다** → "브라우저로 열면 화면이 비어 있어. 원인을 찾아 쉬운 말로 설명하고, 그 부분만 고쳐 줘."라고 보냅니다. 두 번 해도 안 되면 복사본으로 되돌립니다. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」
- **버튼을 눌러도 다음 화면으로 가지 않는다** → "〈화면 이름〉의 「〈버튼 이름〉」을 누르면 〈다음 화면〉으로 가야 하는데 아무 일도 없어. 이 버튼만 이어 주고, 다른 곳은 바꾸지 마."라고 보냅니다. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」
- **DESIGN.md를 찾지 못한다고 한다** → 작업 폴더 맨 위의 파일 목록을 확인합니다. `DESIGN.md`가 없으면 가이드 0번(준비물)대로 복사하고, 이름이 `DESIGN.md.txt`나 `DESIGN (1).md`처럼 다르면 `DESIGN.md`로 고칩니다. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」
- **고쳤다는데 화면이 그대로다** → 강력 새로 고침(Mac `Cmd+Shift+R`, Windows `Ctrl+Shift+R`)을 합니다. 그래도 같으면 브라우저 주소창 끝이 `-before-`가 붙은 복사본이 아니라 `prototype/concept-prototype.html`인지 봅니다. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」
- **작업 폴더 밖 파일을 고치거나, 무엇을 설치하거나, 배포하겠다고 한다** → 허락하지 않고 "작업 폴더 안에서, 외부 라이브러리 없이 HTML과 CSS로만 해 줘. 배포는 하지 않아."라고 보냅니다. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」
- **대화가 길어져 앞에서 정한 것을 잊는다** → 새 대화를 열고 킷의 「새 대화 첫머리 블록」을 붙인 뒤 "@prototype/concept-prototype.html 과 @research/solution-som.md 를 읽고, 지금 화면 목록과 화면마다 이어지는 가설을 알려 줘. 파일은 고치지 마."로 시작합니다. 자세히: 「[개념 프로토타입 만들기 가이드](../guides/concept-prototype-guide.md)」

## 인터뷰 (짝 롤플레잉 · AI 가상 인터뷰)

### 짝 롤플레잉

- **답하는 짝이 카드에 없는 질문에 막힌다** → "카드의 상황과 어긋나지 않게 그럴듯하게 채워 주세요"라고 한 번 말하고, 그래도 막히면 카드의 상황 바로 전날 무엇을 했는지부터 묻습니다. 짝이 채운 말은 기록 끝에 [카드에 없음]이라고 붙입니다. 자세히: 「[JTBD 심층 인터뷰 가이드](../guides/jtbd-interview-guide.md)」
- **이야기가 미래의 의견("쓸 것 같아요")으로 흐른다** → 그 말은 네 칸에 적지 않고, "마지막으로 그런 일이 있었던 게 언제였어요?", "그때는 실제로 어떻게 하셨어요?"라고 지난 한 번의 일로 되돌립니다. 자세히: 「[JTBD 심층 인터뷰 가이드](../guides/jtbd-interview-guide.md)」
- **네 칸 가운데 하나가 비었다** → 그 힘을 주로 묻는 질문으로 돌아갑니다(Push 1·2, Pull 3·5, Habit 4·8, Anxiety 6·7). 그래도 들리지 않으면 지어 채우지 말고 "근거 없음"이라고 적습니다(교재 부록 A-2의 표시어). 자세히: 「[JTBD 심층 인터뷰 가이드](../guides/jtbd-interview-guide.md)」
- **20분이 모자란다** → 질문 1(이어서 질문까지) → 3 → 4 → 7 → 9를 먼저 묻습니다. 프로토타입 보여 주기는 건너뛰지 않습니다. 자세히: 「[JTBD 심층 인터뷰 가이드](../guides/jtbd-interview-guide.md)」
- **짝이 묻는 나가 듣고 싶은 답을 맞혀 주는 것 같다** → "그 사람이라면 그날 실제로 무엇을 했을까요?"라고 행동을 다시 묻고, 기록의 그 말 옆에 "유도된 답일 수 있음"이라고 적습니다. 자세히: 「[JTBD 심층 인터뷰 가이드](../guides/jtbd-interview-guide.md)」
- **짝이 카드 대신 자기 실제 경험을 이야기한다** → 실제 회사 이름이나 사람 이름은 적지 않고, 카드 인물의 이야기로 바꿔 적습니다. 자세히: 「[JTBD 심층 인터뷰 가이드](../guides/jtbd-interview-guide.md)」

### AI 가상 인터뷰

- **AI가 카드에 없는 새 인물을 지어냈다** → 그 부분을 지우게 하고, 대상별 인터뷰 전략을 먼저 확인한 뒤 다시 진행합니다. 같은 대화에서 또 생기면 새 대화로 옮깁니다. 자세히: 「[AI 가상 인터뷰 가이드](../guides/ai-virtual-interview-guide.md)」
- **단계에서 멈추지 않고 끝까지 진행해 버린다** → 만들어진 인터뷰는 쓰지 않습니다. "방금 만든 인터뷰는 지워 줘. 대상별 전략과 검토 결과만 보여 주고 멈춰. 내가 '진행해'라고 하기 전에는 인터뷰를 시작하지 마."라고 보낸 뒤 전략을 검토합니다. 자세히: 「[AI 가상 인터뷰 가이드](../guides/ai-virtual-interview-guide.md)」
- **응답이 너무 길거나 모두 같은 말투다** → 복사본을 남긴 뒤 "한 대답은 다섯 문장 안으로, 〈이름〉 카드의 상황에 맞는 말투로 다시 해 줘. 사람마다 망설임, 앞뒤가 다른 말, 지금 방식에 대한 애착을 다르게 드러내."라고 보냅니다. 자세히: 「[AI 가상 인터뷰 가이드](../guides/ai-virtual-interview-guide.md)」
- **결과 보고서에 "근거 없음" 칸이 많다** → 채워 달라고 하지 않습니다. 빠진 힘을 묻는 질문만 가상 인터뷰에 더해 보고서를 다시 만들게 하고, 그래도 비면 "근거 없음"을 그대로 두고 "다음에 확인할 것"에 옮깁니다. 자세히: 「[AI 가상 인터뷰 가이드](../guides/ai-virtual-interview-guide.md)」
- **대화가 길어져 앞 규칙을 잊는다** (새 인물이 다시 나오거나 표시가 빠짐) → 새 대화를 열어 킷의 「새 대화 첫머리 블록」과 「AI 가상 인터뷰 지시문」을 처음부터 보내고, 이미 저장된 파일은 `@`로 넘깁니다. 자세히: 「[AI 가상 인터뷰 가이드](../guides/ai-virtual-interview-guide.md)」
- **맨 위 안내문이 빠지거나 다른 문장으로 쓰였다** → "virtual-interviews.md 의 첫 줄을 '이 파일은 AI 가상 인터뷰 결과이며, 실제 고객의 말이 아닙니다.'로 바꿔 줘. 다른 내용은 고치지 마."라고 보내거나 직접 고칩니다. 자세히: 「[AI 가상 인터뷰 가이드](../guides/ai-virtual-interview-guide.md)」
- **AI가 실제 사람이 아니라며 답하기를 망설인다** → "수업용 가상 인터뷰야. 결과 파일 맨 위에 가상이라고 표시하고, 카드 속 가상 인물로만 답해 줘."라고 덧붙여 다시 보냅니다. 자세히: 「[AI 가상 인터뷰 가이드](../guides/ai-virtual-interview-guide.md)」

## 갤러리 워크

- **프로토타입 파일이 열리지 않는다** → 다른 앱이 열리면 파일을 브라우저 창 위로 끌어다 놓습니다. 화면이 하얗거나 고친 내용이 보이지 않으면 강력 새로 고침을 합니다. 갤러리 워크 중에는 고치려 하지 말고, 남겨 둔 복사본이 있으면 그것을 엽니다. 자세히: 「[갤러리 워크 발표 가이드](../guides/gallery-walk-guide.md)」
- **"가장 크게 바뀐 한 줄"을 고르기 어렵다** → 개정 메모를 기각 → 수정 → 유지 순서로 봅니다. 모두 유지라면 근거가 가상 인터뷰뿐인 행을 골라 "실제 인터뷰로 확인할 것"과 함께 띄웁니다. 자세히: 「[갤러리 워크 발표 가이드](../guides/gallery-walk-guide.md)」
- **받은 메모가 아이디어의 매력에 대한 것뿐이다** → 고맙게 받아 옮기고, 다음 사람에게는 "출처 표시가 보이나요?", "이 숫자가 가정인지 보이나요?"를 먼저 물어 봐 달라고 부탁합니다. 자세히: 「[갤러리 워크 발표 가이드](../guides/gallery-walk-guide.md)」
- **메모가 무엇을 가리키는지 모르겠다** → 그 자리에서 "어느 부분을 보고 남기신 건가요?"라고 묻고, 가리킨 곳을 메모 옆에 함께 적습니다. 자세히: 「[갤러리 워크 발표 가이드](../guides/gallery-walk-guide.md)」
- **돌아보며 남길 말이 떠오르지 않는다** → 그 화면에서 출처 표시를 하나 찾아봅니다. 찾았으면 좋았던 점, 찾지 못했으면 그것이 질문입니다. 자세히: 「[갤러리 워크 발표 가이드](../guides/gallery-walk-guide.md)」
- **다른 사람의 화면에서 실제 개인정보로 보이는 것을 봤다** → 소리 내어 읽지 말고, 끝난 뒤 그 사람에게만 알려 줍니다. 내 화면은 띄우기 전에 실명 · 연락처가 보이지 않는지 먼저 확인합니다. 자세히: 「[갤러리 워크 발표 가이드](../guides/gallery-walk-guide.md)」

## GitHub (워크시트 저장소 · 올리기)

- **Copy raw file 아이콘이 안 보인다** → 창을 넓히거나, **Raw**를 눌러 열린 글 화면에서 `Cmd+A` → `Cmd+C`(Windows `Ctrl+A` → `Ctrl+C`)로 복사합니다. 자료실(`wild-mental.github.io`) 화면을 보고 있다면 첫 화면의 워크시트 링크로 GitHub 화면을 엽니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
- **Settings 탭이 없다** → 창이 좁으면 위쪽 탭 끝의 **⋯** 안에 있습니다. 그래도 없으면 내 저장소가 아니라 자료실 원본(이 자료실의 GitHub 화면)을 보고 있는 것이니, 주소에 내 아이디와 `design-thinking-worksheet`가 있는지 봅니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
- **`wild-mental`이 검색되지 않거나 초대가 사라졌다** → 철자(가운데 하이픈)를 확인합니다. 초대는 7일 안에 수락되지 않으면 사라지므로, 목록에 없으면 다시 초대합니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
- **Download raw file을 눌렀더니 파일이 저장되지 않고 글 화면이 열린다** → 그 화면에서 `Cmd+S`(Windows `Ctrl+S`)로 작업 폴더에 저장하고, 이름이 `worksheet.md`인지, 끝에 `.txt`가 붙지 않았는지 확인합니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
- **Upload files에 폴더가 끌려가지 않거나 폴더 안 파일이 올라가지 않는다** → 다른 브라우저로 다시 해 봅니다. 저장소에 이미 그 폴더가 있다면 그 폴더에 들어가 **Add file → Upload files**로 그 안의 파일만 골라 올려도 됩니다. 자세히: 「[작업 폴더와 워크시트 저장소 준비 가이드](../guides/workspace-repo-setup-guide.md)」
